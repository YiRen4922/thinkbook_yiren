# 字典序 · Flashcards

### 一、字典序的定义

什么是字典序（Lexicographic Order）？
?
字典序是**逐字符比较**两串对应位置的字符编码（ASCII/Unicode），遇第一对不同字符时**编码小者排前**（即该串"较小"）；若一个串是另一个串的前缀，则**较短串排前**（较短者"较小"）。
<!--SR:!2026-09-15,4,270-->

字典序比较的三步法是什么？
?
① 从第一个字符起，逐位比较两串对应字符的编码；
② 遇到第一对**不同字符**时，编码小者排前（该串较小）；
③ 若较短串是较长串的**前缀**（前 $n$ 个字符全相同，较长串还有剩余），则较短串较小。
<!--SR:!2026-09-15,4,270-->

长度是否影响字典序？
?
**长度本身不影响字典序**，只有当一个串是另一个串的前缀时，长度才有意义——此时较短的串较小。例如 `"abc" < "abd"`（第一个不同字符处 `c < d`），而 `"abc" < "abcd"`（`abc` 是 `abcd` 的前缀）。

### 二、ASCII 编码与大小写关系

ASCII 中，大写字母、小写字母、数字的编码范围分别是多少？
?
- 数字 `'0'`~`'9'`：48~57
- 大写字母 `'A'`~`'Z'`：65~90
- 小写字母 `'a'`~`'z'`：97~122

整体大小关系：**数字 < 大写字母 < 小写字母**。
<!--SR:!2026-09-15,4,270-->

ASCII 中，大写和小写字母之间的编码差是多少？
?
差值恒为 **32**。例如 `'a'`(97) - `'A'`(65) = 32，`'b'`-`'B'`=32。这个规律可用于大小写转换：`ch ^= 32`（异或 32，位运算实现大小写翻转）。
<!--SR:!2026-09-15,4,270-->

按字典序，以下字符串从小到大排列是？`"apple"`, `"Apple"`, `"banana"`, `"Banana"`, `"app"`
?
**`"Apple" < "Banana" < "apple" < "banana" < "app"`**？❌
正确答案：**`"Apple" < "Banana" < "apple" < "app" < "banana"`**？❌

逐个比较：
- `"Apple"` vs `"Banana"`：`'A'`(65) < `'B'`(66) → `"Apple"` 更小 ✓
- `"Banana"` vs `"apple"`：`'B'`(66) < `'a'`(97) → `"Banana"` 更小 ✓
- `"apple"` vs `"app"`：前 3 位相同，`"app"` 是 `"apple"` 的前缀 → `"app"` 更小
- `"apple"` vs `"banana"`：`'a'`(97) < `'b'`(98) → `"apple"` 更小

最终排序：**`"Apple" < "Banana" < "app" < "apple" < "banana"`**

### 三、特殊情况与易错

`'a'` 和 `'B'` 谁大？
?
`'B'`(66) < `'a'`(97)，所以 **`'B'` 更小**，即 `"B" < "a"`。
很多人直觉上以为小写字母更"靠前"，实际在 ASCII 中大写字母编码更小，字典序中**大写排在小写前面**。
<!--SR:!2026-09-15,4,270-->

两个长度不同但完全相同的串（如 `"abc"` 和 `"abc"`)，字典序关系是什么？
?
相等，字典序认为二者**相同**（不算小也不算大）。字典序只有三种关系：`<`、`=`、`>`。
<!--SR:!2026-09-13,2,210-->

字典序在 408 串章节中有什么应用？
?
① **串的比较**：`StrCompare(S, T)` 的底层逻辑就是字典序；② **KMP/模式匹配**：全序关系下的串比较是算法正确性的基础；③ **选择题/排序题**：给出若干字符串，要求按字典序排序。
<!--SR:!2026-09-13,2,210-->
