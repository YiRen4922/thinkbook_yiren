# 并查集 · Flashcards

### 一、基本概念

并查集是什么？名字的含义是什么？
?
一种维护**不相交集合**（每个元素属于且仅属于一个集合）的数据结构，主要回答两类问题：
- 元素 a、b 是否在**同一个集合**中？
- 如何把两个集合**合并**？
名字来源：**并**（Union 合并）+ **查**（Find 查找）+ **集**（集合）。
<!--SR:!2026-09-23,5,230-->


并查集用什么存储结构？如何表示？
?
用**双亲表示法**的数组 $S[]$：下标表示元素编号，$S[i]$ 存储 $i$ 的**双亲**下标。
- 根结点存**负数**，其绝对值表示该集合的元素个数
- 例：$S = [-3, 1, 1, -1]$ 表示 2、3 的双亲是 1，根 1 的集合含 3 个元素；4 是根但单独成集
<!--SR:!2026-09-18,2,230-->

并查集的初始化怎么做？
?
每个元素自成一个集合：$S[i] = -1$（i 是自己的根，集合大小为 1）。
```c
void Init(int n) {
    for (int i = 1; i <= n; i++)
        S[i] = -1;
}
```
<!--SR:!2026-09-18,2,230-->


### 二、基本操作

Find 操作的功能和实现是什么？
?
功能：查找元素 x 所在集合，返回**根结点**下标。
```c
int Find(int x) {
    while (S[x] >= 0)     // 不是根就沿双亲往上走
        x = S[x];
    return x;
}
```
最坏情况（树退化为链）下一次查找为 $O(n)$。
<!--SR:!2026-09-23,5,230-->


Union 操作的功能和实现是什么？
?
功能：把 x、y 所在的两个集合合并。
```c
void Union(int x, int y) {
    int rx = Find(x), ry = Find(y);
    if (rx != ry)
        S[rx] = ry;       // 把 x 所在集合的根挂到 y 所在集合的根下
}
```
合并动作本身 O(1)，总开销主要来自两次 Find。
<!--SR:!2026-09-23,5,230-->


并查集不进行优化会有什么问题？
?
如果合并时随意把一棵树挂到另一棵树下，树可能**退化成一条链**，Find 最坏 $O(n)$，含 m 次操作的序列最坏退化到 $O(mn)$。
两种优化手段：**按规模（秩）合并** + **路径压缩**。
<!--SR:!2026-09-23,5,230-->


### 三、优化

按规模合并（Union by Size）的思想和实现是什么？
?
把**规模小**的树并入**规模大**的树，避免树长高。根存负的规模，合并时更新规模（更负表示规模更大）。
```c
void Union(int x, int y) {
    int rx = Find(x), ry = Find(y);
    if (rx == ry) return;
    if (S[rx] > S[ry]) {        // rx 规模更小，并入 ry
        S[ry] += S[rx];         // 更新 ry 的规模（更负）
        S[rx] = ry;
    } else {
        S[rx] += S[ry];         // 否则把 ry 并入 rx
        S[ry] = rx;
    }
}
```
仅按规模合并时树高 $O(\log n)$，Find 最坏 $O(\log n)$。
<!--SR:!2026-09-18,2,230-->


路径压缩（Path Compression）的思想和实现是什么？
?
Find 时把**沿途所有结点直接挂到根**下，使之后的查找接近 O(1)。
```c
int Find(int x) {
    int root = x;
    while (S[root] >= 0) root = S[root];   // 1. 先找到根
    while (x != root) {                     // 2. 沿途结点全部指向根
        int p = S[x];
        S[x] = root;
        x = p;
    }
    return root;
}
```
<!--SR:!2026-09-18,2,230-->


两种优化都使用后，并查集的复杂度是多少？
?
同时采用**按规模合并 + 路径压缩**，单次操作的均摊时间复杂度为 $O(\alpha(n))$——$\alpha(n)$ 是反阿克曼函数，增长极慢（n 达到宇宙原子数量级时也几乎不超过 4），可视为**常数级**。
<!--SR:!2026-09-18,2,230-->


### 四、应用

并查集有哪些典型应用？
?
- 判断元素是否在**同一集合/同一团体**（亲戚关系、朋友圈）
- 无向图的**连通分量**统计
- 判断图**是否有环**（配合 Kruskal 最小生成树）
- 动态连通性问题（不断加边、随时查连通）
<!--SR:!2026-09-17,2,230-->

如何用并查集判断无向图是否有环？
?
遍历每条边 (u, v)：
- 若 Find(u) == Find(v)：u、v 已在同一连通分量中，加上这条边就**成环**
- 否则 Union(u, v)
总复杂度 O(E·α(n))。
<!--SR:!2026-09-19,3,250-->


并查集在 Kruskal 算法中起什么作用？
?
Kruskal 按**边权从小到大**选边：对每条边用并查集判断两端点是否已连通——**不在同一集合则选入并合并**（不构成环），在同一集合则跳过。选满 $n - 1$ 条边即得最小生成树。
<!--SR:!2026-09-19,1,190-->
