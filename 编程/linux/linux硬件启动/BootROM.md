运行于Soc片内SRAM中
BootROM 是固化在 SoC 内部的一小块只读存储器（ROM）。SoC 上电后，CPU 第一条指令就是从 BootROM 开始执行。它会读取特定的引脚电平（如 SARADC 引脚）或 eFuse 状态，来决定从哪里启动（比如：SPI Flash、eMMC、SD 卡、USB OTG 等）。

实际 RK3588 的启动选择由硬件启动配置决定，例如启动介质相关的配置/引脚。

另外还存在用于恢复/下载的模式，例如：

```
MaskROM mode
```

这也是 Rockchip 平台为什么经常能看到：

```
Found One LOADER Device
Found One MASKROM Device
```


以 RK3588 为例，其内部固化的 **BootROM（启动 ROM）** 是整个系统启动的绝对起点。它是一段在芯片出厂时就被写入、无法修改的代码，相当于芯片的“本能反应”。

BootROM 的完整执行流程，可以清晰地分为以下几个核心阶段：

### ⚡️ 第一阶段：上电复位与基础环境建立
当芯片检测到电源稳定后，会释放复位信号，CPU（通常是主核 Cortex-A76 或 A55）从固定的物理地址 `0xFFFF0000` 开始取指，执行 BootROM 的第一条指令。

在这个瞬间，系统会进行最基础的硬件初始化：
*   **时钟与电源**：初始化锁相环（PLL），确保系统时钟稳定运行。
*   **存储空间**：初始化芯片内部的一小块 **SRAM**（静态随机存取存储器）。这块 SRAM 只有几百 KB，但它是 BootROM 运行时唯一的“工作台”。
*   **运行环境**：配置 CPU 的栈指针（SP），为后续执行 C 代码做好准备。

### 🔍 第二阶段：启动介质探测与优先级仲裁
BootROM 接下来会按照预设的优先级顺序，扫描各种可能的启动介质，寻找合法的第二阶段引导程序（通常是 TPL/SPL 或 DDR 初始化固件）。

以 RK3588 为例，其探测顺序和固件读取位置有严格规定：

| 优先级   | 启动介质              | 固件读取起始位置                          | 说明            |
| :---- | :---------------- | :-------------------------------- | :------------ |
| **1** | **SPI NOR Flash** | `0x8000` 偏移处                      | 探测到有效固件则直接启动。 |
| **2** | **eMMC**          | 第 64 个扇区 (LBA 64，即 `0x20000` 字节处) | 最常见的启动方式。     |
| **3** | **SD/MMC 卡**      | 第 64 个扇区 (LBA 64)                 | 常用于系统恢复或开发调试。 |

这个优先级顺序是**硬编码**在 BootROM 中的。在实际项目中，如果同时插入了 eMMC 和 SD 卡，系统会默认从优先级更高的 eMMC 启动。

### 🛡️ 第三阶段：固件校验与安全启动 (Secure Boot)
找到固件后，BootROM 不会盲目执行。如果芯片开启了安全启动功能，它会执行严格的校验流程，建立**硬件信任根（Root of Trust）**。

*   **验签流程**：BootROM 会读取固件头部的公钥，并计算其哈希值。然后，将这个哈希值与烧录在芯片 **OTP eFuse**（一次性可编程存储器）中的哈希值进行比对。
*   **决策**：如果哈希值不匹配，说明固件被篡改或非官方授权，BootROM 将**拒绝加载并停止启动**，系统将无法开机。
*   **信任链传递**：验证通过后，BootROM 将控制权交给固件，并信任该固件。后续的 U-Boot、Kernel 的校验则由这个被信任的固件继续完成，形成一条完整的信任链。

### 📥 第四阶段：加载与跳转至 SRAM
如果校验通过（或未开启安全启动），BootROM 就会将找到的固件（如 TPL 或 DDR 初始化二进制文件）从存储介质读取到内部 SRAM 中。

由于 SRAM 空间有限，这个固件通常很小，它的核心任务就是**初始化 DDR 内存**。BootROM 完成加载后，会设置好 CPU 的通用寄存器（如 ARM64 架构下，`x0` 寄存器通常用于传递参数），然后**跳转到 SRAM 中固件的入口点**，将控制权正式移交。

### 🚨 特殊模式：MaskROM 下载模式
如果 BootROM 扫描了所有预设的启动介质，都没有找到有效的固件，它不会“死机”，而是会**自动进入 MaskROM 模式**。

在此模式下，BootROM 会通过 USB OTG 接口暴露一个设备（Rockchip 的 USB Vendor ID 为 `0x2207`）。PC 端的工具（如 `rkdeveloptool`）可以利用这个接口，将固件（如 `loader.bin`）直接下载到 SRAM 或 DDR 中并执行。这是**固件烧录和系统恢复的底层关键入口**。

### 💎 总结
RK3588 的 BootROM 流程是一个**优先级仲裁、安全校验、加载跳转**的标准化过程。它作为芯片上电后的第一段代码，通过读取启动介质、执行安全校验，将更复杂的 DDR 初始化任务交给后续固件，从而为加载 U-Boot 和 Kernel 铺平道路。
