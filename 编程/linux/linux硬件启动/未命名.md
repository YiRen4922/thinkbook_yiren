**U-Boot 结束后 → Kernel 运行到系统启动的完整流程**（以 RK3588 ARM64 为例）

U-Boot 完成内核镜像（`Image`）、设备树（DTB）和可选 initramfs 的加载后，通过 `booti` / `bootm` 跳转到内核入口。此时 CPU0 处于 **EL2 或 EL1**，MMU 关闭，D-cache 关闭，I-cache 可选开启。U-Boot 传递的关键参数：

- **x0** = DTB 物理地址（必须 8 字节对齐，大小 ≤ 2 MB）
- **x1~x3** = 0（保留）

### 1. 内核入口与早期汇编初始化（`arch/arm64/kernel/head.S`）

入口点是 `primary_entry`（Image 头部 magic `0x644d5241` = “ARM\x64”）。

主要步骤：

1. **禁用中断**（`daifset #0xf`）。
2. **保存 boot args**（DTB 地址存入 x21）。
3. **EL 级别处理**（`el2_setup`）：如果当前在 EL2，配置 hypervisor 相关寄存器，准备降级到 EL1。
4. **创建早期页表**（`__create_page_tables`）：
   - Identity mapping（idmap_pg_dir）用于开启 MMU。
   - 内核映射（init_pg_dir）。
5. **CPU 设置**（`__cpu_setup`）：初始化 SCTLR_EL1、TCR 等。
6. **开启 MMU**（`__primary_switch` → `enable_mmu`）：
   - 设置 TTBR0_EL1 / TTBR1_EL1。
   - 开启 MMU（SCTLR_EL1.M = 1）。
7. **切换到虚拟地址空间**（`__primary_switched`）：
   - 设置异常向量表（VBAR_EL1）。
   - 建立内核栈（`init_thread_union`）。
   - 清零 BSS。
   - 跳转到 C 语言入口 **`start_kernel()`**。

此时只有 CPU0 在运行，其他 7 个核心（3×A76 + 4×A55）仍处于复位或等待状态。

### 2. 内核核心初始化（`start_kernel()` in `init/main.c`）

这是架构无关的真正入口，按严格顺序执行：

| 阶段 | 关键函数 | 作用 |
|------|----------|------|
| 早期准备 | `boot_cpu_init()`、`setup_arch()` | 解析 DTB、初始化 memblock、设置内存布局、早期控制台 |
| 内存管理 | `mm_init()`、`mem_init()` | 建立 buddy 系统、SLAB/SLUB、vmalloc |
| 调度器 | `sched_init()` | 初始化进程调度 |
| 中断与时钟 | `init_IRQ()`、`time_init()` | GICv3 初始化、架构定时器（arch_timer） |
| SMP 准备 | `smp_prepare_cpus()` | 为多核做准备 |
| 驱动模型 | `driver_init()` | 初始化设备模型、平台总线 |
| 其他 | `vfs_caches_init()`、`proc_root_init()` 等 | VFS、procfs、cgroup 等 |

**RK3588 特有点**：
- DTB 中通过 `enable-method = "psci"` 描述所有 CPU 节点。
- 通过 **PSCI**（由 ATF/BL31 提供）唤醒其他核心。
- 解析 Rockchip 特定节点（时钟、电源域、IOMUX、PCIe、NPU 等）。

### 3. 多核启动（SMP Bring-up）

在 `rest_init()` → `kernel_init()` 前或期间：

- 主核调用 `smp_init()` / `bringup_nonboot_cpus()`。
- 通过 **PSCI CPU_ON** SMC 调用唤醒其他 7 个核心。
- 从核从 `secondary_entry` 进入，完成自身初始化后加入调度器。
- 日志中可见：
  ```
  smp: Bringing up secondary CPUs ...
  Detected VIPT I-cache on CPU1
  ...
  ```

RK3588 big.LITTLE 拓扑（4×A76 + 4×A55）在 DTS 中明确描述，内核会正确设置 capacity-dmips-mhz 等调度参数。

### 4. 根文件系统挂载与用户空间启动

1. **initramfs / initrd**（如果存在）：
   - 内核解压并挂载为临时根文件系统。
   - 执行 `/init`（通常是 busybox 或 systemd 的早期阶段）。
   - 负责加载必要模块、发现真实根设备（eMMC / NVMe / SD 等）。

2. **真实根文件系统挂载**：
   - 根据 `bootargs` 中的 `root=`（如 `root=PARTUUID=...` 或 `root=/dev/mmcblk0pX`）挂载。
   - 常见参数：`rootwait`、`rootfstype=ext4`、`rw` 等。
   - 切换根（`pivot_root` 或 `switch_root`）。

3. **执行 init 进程（PID 1）**：
   - 通常是 `/sbin/init` → **systemd**（现代发行版）或 busybox init。
   - systemd 按依赖关系启动服务：
     - 本地文件系统挂载（local-fs.target）
     - 网络（network.target）
     - 登录服务（getty、sshd 等）
     - 图形界面（如果配置了 display-manager）

4. **系统完全启动**：
   - 出现登录提示符或桌面。
   - 所有驱动完成 probe，用户空间服务运行。

### 关键内存布局示例（典型 RK3588）

- 内核 Image：通常加载到 0x02080000 或更高地址
- DTB：0x0a000000 附近
- initrd：紧随其后
- 内核运行后虚拟地址空间从 `PAGE_OFFSET` 开始映射

### 总结流程简图

```
U-Boot (booti)
    ↓ (x0 = DTB)
primary_entry (head.S)
    ↓
开启 MMU + 页表
    ↓
start_kernel()
    ├── setup_arch() + DTB 解析
    ├── 内存/调度/中断初始化
    ├── SMP 通过 PSCI 唤醒其他核心
    ├── 驱动初始化
    └── rest_init() → kernel_init()
            ↓
        挂载 rootfs
            ↓
        执行 /sbin/init (systemd)
            ↓
        用户空间服务启动 → 系统可用
```

这个过程在 RK3588 上与标准 ARM64 Linux 高度一致，主要差异在于 PSCI 多核启动、Rockchip 特定时钟/电源驱动以及 DTB 内容。如果使用官方 5.10/6.1 SDK 内核或主线内核（6.7+），整体流程相同，只是驱动支持完整度不同。
