> 智能指针是 RAII（资源获取即初始化）的典范，用于**自动管理动态内存**，避免内存泄漏和悬垂指针。  
> 核心头文件：`<memory>`

## 1. `std::unique_ptr` —— 独占所有权

**特点**：同一时刻只能有一个 `unique_ptr` 指向某对象，**不允许拷贝**，但可以**移动**（转移所有权）。

### 创建

```cpp
#include <memory>

auto p1 = std::make_unique<int>(42);          // 推荐
std::unique_ptr<int> p2(new int(42));         // 可用，但不推荐（可能异常不安全）
```

### 转移所有权（移动）

```cpp
std::unique_ptr<int> p1 = std::make_unique<int>(10);
std::unique_ptr<int> p2 = std::move(p1);      // p1 变为空，p2 拥有资源
// p1 现在为空，不能解引用
```

### 作为函数返回值（自动移动）

```cpp
std::unique_ptr<int> createInt() {
    return std::make_unique<int>(99);          // 编译器自动使用移动语义
}

auto p = createInt();                         // 所有权转移给 p
```

### 使用场景

- **工厂函数**：返回动态创建的对象的唯一所有权。
- **容器中管理资源**：如 `std::vector<std::unique_ptr<Widget>>`。
- **PIMPL 惯用法**（隐藏实现细节）。

### 自定义删除器

```cpp
auto deleter = [](FILE* f) { if(f) fclose(f); };
std::unique_ptr<FILE, decltype(deleter)> fp(fopen("log.txt", "w"), deleter);
```

## 2. `std::shared_ptr` —— 共享所有权

**特点**：多个 `shared_ptr` 可以**共享同一个对象**，内部维护**引用计数**（控制块），当最后一个 `shared_ptr` 销毁时释放对象。

### 创建

```cpp
auto sp1 = std::make_shared<Widget>();        // 推荐，一次内存分配（对象+控制块）
std::shared_ptr<Widget> sp2(new Widget());    // 可用，但两次内存分配，性能稍差
```

### 拷贝与赋值（引用计数增加）

```cpp
auto sp1 = std::make_shared<int>(100);
auto sp2 = sp1;                               // 拷贝，引用计数变为 2
auto sp3 = std::move(sp1);                    // 移动，sp1 为空，sp3 接管，引用计数不变
```

### 使用场景

- **多个对象需要共享同一资源**（如多个视图共享同一数据）。
- **缓存系统**：多个地方需要访问同一数据。
- **图结构**：节点被多个边引用，生命周期不确定。

### 循环引用 —— 导致内存泄漏

```cpp
struct Node {
    std::shared_ptr<Node> next;
};
auto a = std::make_shared<Node>();
auto b = std::make_shared<Node>();
a->next = b;
b->next = a;   // 循环引用，a 和 b 永远无法释放！
```

## 3. `std::weak_ptr` —— 弱引用，打破循环

**特点**：`weak_ptr` 不增加引用计数，用于**观察** `shared_ptr` 管理的对象，但不拥有它。需要访问对象时，通过 `lock()` 获得临时的 `shared_ptr`。

### 创建与使用

```cpp
std::shared_ptr<int> sp = std::make_shared<int>(42);
std::weak_ptr<int> wp = sp;                   // 从 shared_ptr 构造

if (auto spt = wp.lock()) {                  // 尝试提升为 shared_ptr
    // 使用 spt，此时对象存活
    std::cout << *spt << '\n';
} else {
    // 对象已被销毁
    std::cout << "对象已释放\n";
}
```

### 使用场景

- **打破循环引用**：将 `shared_ptr` 中的环改为 `weak_ptr`。
- **观察者模式**：订阅者持有目标的 `weak_ptr`，若目标销毁则自动失效。
- **缓存**：缓存对象用 `weak_ptr`，若内存不足可被回收。

**改进上面的循环引用示例**：

```cpp
struct Node {
    std::weak_ptr<Node> next;   // 改为 weak_ptr，打破循环
};
```

## 4. 选择指南

| 场景 | 推荐智能指针 |
|------|-------------|
| 明确只有一个所有者 | `unique_ptr` |
| 需要多个所有者共享资源 | `shared_ptr` |
| 需要观察但不拥有，打破循环 | `weak_ptr` |
| 作为函数参数（只读取资源） | 传递裸指针或引用（但确保生命周期） |
| 作为函数参数（转移所有权） | 按值传 `unique_ptr`（调用方 `std::move`） |
| 作为函数参数（共享所有权） | 按值传 `shared_ptr` 或 `const shared_ptr&` |

## 5. 常见陷阱与最佳实践

### ❌ 不要用裸指针管理动态内存

```cpp
// 坏习惯
int* p = new int(10);
delete p;   // 容易忘记

// 好习惯
auto p = std::make_unique<int>(10);
```

### ❌ 尽量避免 `get()`，除非必须与 C 接口交互

```cpp
auto sp = std::make_shared<Widget>();
Widget* raw = sp.get();   // 仅用于传递给 C 函数，不要用它管理生命周期
```

### ✅ 优先使用 `make_unique` / `make_shared`

- 更简洁，异常安全（避免 `new` 和智能指针构造之间的间隙）。
- `make_shared` 一次分配对象和控制块，性能更高。

### ❌ 不要将 `this` 直接交给 `shared_ptr`

```cpp
class Bad {
public:
    std::shared_ptr<Bad> getShared() {
        return std::shared_ptr<Bad>(this);   // 错误！会导致多个控制块
    }
};
```

### ✅ 正确做法：继承 `std::enable_shared_from_this`

```cpp
class Good : public std::enable_shared_from_this<Good> {
public:
    std::shared_ptr<Good> getShared() {
        return shared_from_this();   // 安全
    }
};
```

### ❌ 循环引用一定要用 `weak_ptr` 打破

## 6. 综合示例

```cpp
#include <iostream>
#include <memory>
#include <vector>

class File {
public:
    File(const std::string& name) : name(name) { std::cout << "Open " << name << '\n'; }
    ~File() { std::cout << "Close " << name << '\n'; }
    void write(const std::string& data) { /* ... */ }
private:
    std::string name;
};

// 工厂函数：返回 unique_ptr，独占资源
std::unique_ptr<File> createFile(const std::string& name) {
    return std::make_unique<File>(name);
}

// 多个读者共享同一个 File（shared_ptr）
void readOnly(const std::shared_ptr<File>& file) {
    // 只读操作...
}

int main() {
    auto logFile = createFile("log.txt");   // unique_ptr 独占

    // 多个对象共享资源
    auto sharedFile = std::make_shared<File>("shared.txt");
    std::vector<std::shared_ptr<File>> readers = {sharedFile, sharedFile, sharedFile};
    // 现在引用计数为 4（包括 sharedFile 本身）

    // 避免循环：用 weak_ptr
    std::weak_ptr<File> weakFile = sharedFile;
    // ... 
    return 0; // 自动释放
}
```

## 总结

- **`unique_ptr`**：独占，轻量，无额外开销，**默认首选**。
- **`shared_ptr`**：共享，引用计数，注意循环引用，使用 `weak_ptr` 解环。
- **`weak_ptr`**：不拥有，仅观察，配合 `lock()` 使用。

> **C++ 核心准则**：避免裸 `new` 和 `delete`，使用智能指针表达所有权意图。
