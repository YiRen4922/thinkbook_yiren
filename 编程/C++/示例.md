# 现代 C++ 智能指针实战示例（多线程 + 高性能任务处理）

> [!abstract] 场景说明
> 本示例模拟一个**高性能多线程任务处理系统**：
> - 主线程不断产生大对象任务（模拟图像、矩阵、数据包等）
> - 使用 `std::unique_ptr` **转移所有权**到线程池，避免拷贝
> - 多个工作线程并发处理任务
> - 使用 `std::shared_ptr` 共享配置和结果收集器
> - 使用 `std::weak_ptr` 观察共享资源，避免循环引用
> - 尽量使用 C++11 及以后新特性，并在注释中明确标注

## 完整示例代码

```cpp
//==============================================================
// 现代 C++ 智能指针实战：多线程高性能任务处理
// 编译建议：-std=c++20 -O2 -pthread
//==============================================================

#include <iostream>
#include <memory>               // C++11: 智能指针
#include <vector>
#include <queue>
#include <thread>
#include <mutex>
#include <condition_variable>
#include <atomic>
#include <string>
#include <string_view>          // C++17: string_view
#include <optional>             // C++17: optional
#include <chrono>
#include <ranges>               // C++20: ranges
#include <algorithm>

//==============================================================
// 1. 任务对象（模拟大对象，禁止拷贝，只允许移动）
//==============================================================
struct HeavyTask {
    int id;
    std::vector<double> data;   // 模拟大型数据

    // C++11: 显式删除拷贝，强制使用移动语义
    HeavyTask(const HeavyTask&) = delete;
    HeavyTask& operator=(const HeavyTask&) = delete;

    // C++11: 移动构造 / 移动赋值
    HeavyTask(HeavyTask&&) noexcept = default;
    HeavyTask& operator=(HeavyTask&&) noexcept = default;

    HeavyTask(int id_, size_t size)
        : id(id_), data(size, id_ * 0.1) {}
};

//==============================================================
// 2. 共享配置（用 shared_ptr 管理，多线程只读共享）
//==============================================================
struct SharedConfig {
    int max_threads;
    double scale_factor;
    std::string name;

    // C++11: 构造函数
    SharedConfig(int threads, double scale, std::string n)
        : max_threads(threads), scale_factor(scale), name(std::move(n)) {}
};

//==============================================================
// 3. 结果收集器（用 shared_ptr 共享，多线程安全写入）
//==============================================================
class ResultCollector {
public:
    void add_result(int task_id, double value) {
        std::lock_guard<std::mutex> lock(mutex_);          // C++11: lock_guard
        results_.emplace_back(task_id, value);             // C++11: emplace_back
    }

    // C++17: 返回 optional，表示可能没有结果
    std::optional<std::pair<int, double>> get_last() const {
        std::lock_guard<std::mutex> lock(mutex_);
        if (results_.empty()) return std::nullopt;         // C++17: nullopt
        return results_.back();
    }

    size_t size() const {
        std::lock_guard<std::mutex> lock(mutex_);
        return results_.size();
    }

private:
    mutable std::mutex mutex_;                             // C++11: mutex
    std::vector<std::pair<int, double>> results_;
};

//==============================================================
// 4. 线程池（核心：unique_ptr 转移任务所有权）
//==============================================================
class ThreadPool {
public:
    // C++11: 构造函数接收 shared_ptr
    explicit ThreadPool(std::shared_ptr<SharedConfig> config,
                        std::shared_ptr<ResultCollector> collector)
        : config_(std::move(config)),                      // C++11: move
          collector_(std::move(collector)),
          stop_(false) {

        // C++11: 根据配置启动线程
        for (int i = 0; i < config_->max_threads; ++i) {
            workers_.emplace_back([this, i]() {            // C++11: Lambda + 捕获
                worker_loop(i);
            });
        }
    }

    // C++11: 析构时安全停止
    ~ThreadPool() {
        {
            std::lock_guard<std::mutex> lock(mutex_);
            stop_ = true;
        }
        cv_.notify_all();                                  // C++11: condition_variable

        for (auto& t : workers_) {
            if (t.joinable()) t.join();
        }
    }

    // 核心接口：接收 unique_ptr，转移所有权（零拷贝）
    void submit(std::unique_ptr<HeavyTask> task) {         // C++11: unique_ptr
        {
            std::lock_guard<std::mutex> lock(mutex_);
            tasks_.push(std::move(task));                  // C++11: move 转移所有权
        }
        cv_.notify_one();
    }

private:
    void worker_loop(int worker_id) {
        while (true) {
            std::unique_ptr<HeavyTask> task;

            {
                std::unique_lock<std::mutex> lock(mutex_); // C++11: unique_lock
                // C++11: wait 带谓词，防止虚假唤醒
                cv_.wait(lock, [this]() {
                    return stop_ || !tasks_.empty();
                });

                if (stop_ && tasks_.empty()) return;

                task = std::move(tasks_.front());          // 再次 move，转移给当前线程
                tasks_.pop();
            }

            // 真正处理任务（模拟高性能计算）
            process_task(worker_id, std::move(task));
        }
    }

    void process_task(int worker_id, std::unique_ptr<HeavyTask> task) {
        // 使用 shared_ptr 安全访问共享配置（只读）
        double scale = config_->scale_factor;

        // 模拟计算：对数据进行变换
        double sum = 0.0;
        for (double& v : task->data) {
            v *= scale;
            sum += v;
        }

        // 写入共享结果收集器
        collector_->add_result(task->id, sum);

        // 演示 weak_ptr 的使用：临时观察 collector 是否还活着
        std::weak_ptr<ResultCollector> weak_collector = collector_;  // C++11: weak_ptr
        if (auto shared = weak_collector.lock()) {                   // 安全升级为 shared_ptr
            // 此时可以安全使用
            (void)shared->size();
        }
    }

    std::shared_ptr<SharedConfig>     config_;
    std::shared_ptr<ResultCollector>  collector_;
    std::vector<std::thread>          workers_;            // C++11: thread

    std::queue<std::unique_ptr<HeavyTask>> tasks_;         // 任务队列（独占所有权）
    std::mutex mutex_;
    std::condition_variable cv_;
    std::atomic<bool> stop_;                               // C++11: atomic
};

//==============================================================
// 5. 主函数：演示完整流程
//==============================================================
int main() {
    // C++11: make_shared 一次性分配控制块+对象，性能更好
    auto config = std::make_shared<SharedConfig>(4, 1.5, "HighPerf-Pool");

    auto collector = std::make_shared<ResultCollector>();

    // 创建线程池（共享配置和结果收集器）
    ThreadPool pool(config, collector);

    // 生产 20 个大任务，全部用 unique_ptr 管理并转移
    for (int i = 1; i <= 20; ++i) {
        // C++14: make_unique（C++14 才进入标准）
        auto task = std::make_unique<HeavyTask>(i, 100000);  // 每个任务 10 万 double

        pool.submit(std::move(task));                        // 所有权转移，无拷贝
    }

    // 等待一段时间让任务完成（实际项目中可用更优雅的同步方式）
    std::this_thread::sleep_for(std::chrono::milliseconds(800));  // C++11: chrono

    // 输出结果
    std::cout << "处理完成，共收集结果数量: " << collector->size() << "\n";

    // C++17: structured bindings + optional
    if (auto last = collector->get_last()) {
        auto [id, value] = *last;                            // C++17: 结构化绑定
        std::cout << "最后一个任务 ID: " << id
                  << "，计算结果: " << value << "\n";
    }

    // C++20: 使用 ranges 对结果做简单展示（这里仅演示语法）
    std::vector<int> demo = {1, 2, 3, 4, 5};
    auto even_view = demo | std::views::filter([](int x) { return x % 2 == 0; });  // C++20: ranges + 管道
    std::cout << "Ranges 演示（偶数）: ";
    for (int v : even_view) std::cout << v << " ";
    std::cout << "\n";

    std::cout << "程序正常结束（所有智能指针自动释放资源）\n";
    return 0;
}
```

## 设计要点总结

1. **`unique_ptr` 负责“独占 + 转移”**：大任务对象只存在一份，通过 `std::move` 在主线程 → 队列 → 工作线程之间转移，性能极高。
2. **`shared_ptr` 负责“共享只读/可写资源”**：配置和结果收集器被多个线程安全共享。
3. **`weak_ptr` 负责“安全观察”**：在需要临时访问共享对象时使用，避免延长生命周期或形成环。
4. **全程 RAII**：锁、线程、内存全部自动管理，无手动 `new/delete`。
5. **可直接扩展**：把 `HeavyTask` 换成真实图像、矩阵、网络数据包即可用于生产环境。

# 现代C++智能指针+线程池完整解析

编译命令：`g++ main.cpp -std=c++20 -O2 -pthread`

> 依赖说明：`std::make_unique`是C++14标准；`string_view/optional` C++17；`ranges`、结构化绑定 C++20；线程、智能指针 C++11。 核心设计思想：
> 
> 1. `unique_ptr`：独占所有权，任务对象只移动不拷贝，避免大对象拷贝开销；
> 2. `shared_ptr`：多线程共享只读配置、结果收集器，自动生命周期管理；
> 3. `weak_ptr`：解决`shared_ptr`循环引用，安全探测对象存活；
> 4. 线程池经典生产者‑消费者模型，`condition_variable`条件变量做任务通知。

```cpp
//==============================================================
// 现代 C++ 智能指针实战：多线程高性能任务处理
// 编译建议：-std=c++20 -O2 -pthread
//==============================================================
#include <iostream>
#include <memory>               // C++11: 智能指针 unique_ptr / shared_ptr / weak_ptr
#include <vector>
#include <queue>
#include <thread>               // C++11 std::thread 线程库
#include <mutex>                // C++11 互斥锁
#include <condition_variable>   // C++11 条件变量，线程等待/唤醒
#include <atomic>               // C++11 原子变量，无锁布尔标记
#include <string>
#include <string_view>          // C++17: 只读字符串视图，不拷贝内存
#include <optional>             // C++17: 可选值，表达“可能返回空”，替代裸指针返回
#include <chrono>               // C++11 时间、sleep
#include <ranges>               // C++20: 范围库，管道式视图处理
#include <algorithm>

//==============================================================
// 1. 任务对象（模拟大对象，禁止拷贝，只允许移动）
//==============================================================
struct HeavyTask {
    int id;
    std::vector<double> data;   // 模拟大型计算数据，内存开销大

    // C++11: 删除拷贝构造，禁止对象拷贝，防止大内存复制
    HeavyTask(const HeavyTask&) = delete;
    // 删除拷贝赋值
    HeavyTask& operator=(const HeavyTask&) = delete;

    // C++11: 默认移动构造，允许把资源所有权转移
    HeavyTask(HeavyTask&&) noexcept = default;
    // 默认移动赋值
    HeavyTask& operator=(HeavyTask&&) noexcept = default;

    // 构造函数：id为任务编号，size为内部vector元素数量
    HeavyTask(int id_, size_t size)
        : id(id_), data(size, id_ * 0.1) {}
};

//==============================================================
// 2. 共享配置（用 shared_ptr 管理，多线程只读共享）
// 多个工作线程只读访问，不需要频繁加锁；生命周期由shared_ptr自动管理
//==============================================================
struct SharedConfig {
    int max_threads;        // 线程池最大工作线程数
    double scale_factor;    // 全局计算缩放系数
    std::string name;       // 线程池名字

    // C++11构造函数，std::move把字符串转为右值，避免字符串拷贝
    SharedConfig(int threads, double scale, std::string n)
        : max_threads(threads), scale_factor(scale), name(std::move(n)) {}
};

//==============================================================
// 3. 结果收集器（用 shared_ptr 共享，多线程安全写入）
// 所有工作线程都会往这里写计算结果，内部通过mutex保证线程安全
//==============================================================
class ResultCollector {
public:
    // 添加一条计算结果，lock_guard作用域锁，出作用域自动释放锁
    void add_result(int task_id, double value) {
        std::lock_guard<std::mutex> lock(mutex_);
        results_.emplace_back(task_id, value); // emplace_back原地构造pair，减少拷贝
    }

    // C++17 optional：返回最后一组结果；没有数据返回std::nullopt，代表不存在值
    std::optional<std::pair<int, double>> get_last() const {
        std::lock_guard<std::mutex> lock(mutex_);
        if (results_.empty()) return std::nullopt;
        return results_.back();
    }

    // 获取已经收集到多少条结果
    size_t size() const {
        std::lock_guard<std::mutex> lock(mutex_);
        return results_.size();
    }

private:
    // mutable：const成员函数内部也可以修改mutex，读取接口也需要加锁保护共享数据
    mutable std::mutex mutex_;
    std::vector<std::pair<int, double>> results_;
};

//==============================================================
// 4. 线程池（核心：unique_ptr 转移任务所有权）
// 生产者主线程submit任务；消费者worker线程取任务执行
//==============================================================
class ThreadPool {
public:
    // C++11构造函数，接收两个shared_ptr，std::move转移shared_ptr内部所有权，增加引用计数
    explicit ThreadPool(std::shared_ptr<SharedConfig> config,
                        std::shared_ptr<ResultCollector> collector)
        : config_(std::move(config)),
          collector_(std::move(collector)),
          stop_(false) {
        // 根据配置创建若干工作线程，每个线程执行worker_loop循环
        for (int i = 0; i < config_->max_threads; ++i) {
            workers_.emplace_back([this, i]() {
                worker_loop(i);
            });
        }
    }

    // C++11析构函数：线程池销毁时优雅停止所有线程，防止资源泄漏
    ~ThreadPool() {
        {
            std::lock_guard<std::mutex> lock(mutex_);
            stop_ = true;          // 设置停止标记
        }
        cv_.notify_all();          // 唤醒所有正在wait阻塞的工作线程
        for (auto& t : workers_) {
            if (t.joinable()) t.join(); // 等待每个线程执行完毕再退出
        }
    }

    // 对外提交任务接口：接收unique_ptr<HeavyTask>，**转移独占所有权**，没有对象拷贝
    void submit(std::unique_ptr<HeavyTask> task) {
        {
            std::lock_guard<std::mutex> lock(mutex_);
            tasks_.push(std::move(task)); // move把任务所有权转移进队列
        }
        cv_.notify_one(); // 唤醒一个等待中的工作线程处理任务
    }

private:
    // 工作线程主循环
    void worker_loop(int worker_id) {
        while (true) {
            std::unique_ptr<HeavyTask> task;
            {
                // unique_lock 可以配合condition_variable.wait使用；lock_guard不能用于wait
                std::unique_lock<std::mutex> lock(mutex_);
                // wait(锁,谓词)：条件不满足就解锁阻塞；收到唤醒信号后再检查谓词，抵御虚假唤醒
                cv_.wait(lock, [this]() {
                    return stop_ || !tasks_.empty();
                });

                // 停止标记置true并且任务队列为空，线程直接return退出循环
                if (stop_ && tasks_.empty()) return;

                // 从队列头部move取出任务，所有权转移给局部变量task
                task = std::move(tasks_.front());
                tasks_.pop();
            }
            // 离开锁的作用域，释放互斥锁！其他线程可以继续操作队列
            // 执行任务计算，把task所有权move传入函数
            process_task(worker_id, std::move(task));
        }
    }

    // 真正执行计算逻辑
    void process_task(int worker_id, std::unique_ptr<HeavyTask> task) {
        // shared_ptr config_多线程只读访问，不需要锁
        double scale = config_->scale_factor;

        double sum = 0.0;
        for (double& v : task->data) {
            v *= scale;
            sum += v;
        }
        // 线程安全写入结果收集器
        collector_->add_result(task->id, sum);

        // weak_ptr演示：从shared_ptr构造weak_ptr，不增加引用计数；用于观测对象存活，解决循环引用
        std::weak_ptr<ResultCollector> weak_collector = collector_;
        // lock()：尝试提升weak_ptr为shared_ptr；对象已经销毁返回空shared_ptr
        if (auto shared = weak_collector.lock()) {
            (void)shared->size();
        }
        // 函数结束 task局部unique_ptr出作用域，HeavyTask内存自动释放，无需手动delete
    }

    std::shared_ptr<SharedConfig>     config_;
    std::shared_ptr<ResultCollector>  collector_;
    std::vector<std::thread>          workers_;
    // 任务队列存储unique_ptr，任务对象独占所有权，不发生拷贝
    std::queue<std::unique_ptr<HeavyTask>> tasks_;

    std::mutex mutex_;
    std::condition_variable cv_;
    std::atomic<bool> stop_;  // atomic原子布尔，多线程无锁读写停止标记
};

//==============================================================
// 5. 主函数：演示完整流程
//==============================================================
int main() {
    // make_shared：一次性分配【控制块+对象内存】相比new+shared_ptr构造减少一次内存分配，性能更好
    auto config = std::make_shared<SharedConfig>(4, 1.5, "HighPerf-Pool");
    auto collector = std::make_shared<ResultCollector>();

    // 创建线程池实例
    ThreadPool pool(config, collector);

    // 生产20个大任务
    for (int i = 1; i <= 20; ++i) {
        // C++14 make_unique 创建独占智能指针
        auto task = std::make_unique<HeavyTask>(i, 100000);
        pool.submit(std::move(task)); // move转移所有权进入线程池队列
    }

    // 简单等待任务完成；工业项目不要sleep，要用future、信号量等同步机制
    std::this_thread::sleep_for(std::chrono::milliseconds(800));

    std::cout << "处理完成，共收集结果数量: " << collector->size() << "\n";

    // C++17 optional + structured bindings结构化绑定
    if (auto last = collector->get_last()) {
        auto [id, value] = *last;
        std::cout << "最后一个任务 ID: " << id
                  << "，计算结果: " << value << "\n";
    }

    // C++20 ranges库管道语法演示，只生成视图，不拷贝容器
    std::vector<int> demo = {1, 2, 3, 4, 5};
    auto even_view = demo | std::views::filter([](int x) { return x % 2 == 0; });
    std::cout << "Ranges 演示（偶数）: ";
    for (int v : even_view) std::cout << v << " ";
    std::cout << "\n";

    std::cout << "程序正常结束（所有智能指针自动释放资源）\n";
    return 0;
}
```

# 代码分段解析

## 一、所有权模型梳理

1. **`std::unique_ptr<HeavyTask>`**

- **独占所有权**：同一时刻只能有一个`unique_ptr`持有对象；只能`std::move`转移，不能拷贝。
- 本代码中HeavyTask内部是大vector，如果拷贝对象代价极高；删除拷贝构造函数，强制移动语义。
- 任务从main创建 → move submit进队列 → worker线程move取出 → move传入process_task，函数结束自动释放内存，全程没有大对象拷贝。

2. **`std::shared_ptr<SharedConfig>` / `std::shared_ptr<ResultCollector>`**

- **共享所有权**，引用计数机制；多个线程可以同时持有同一个对象。
- `SharedConfig`只读，多线程读安全，不需要锁。
- `ResultCollector`会多线程写，所以内部成员方法全部加`mutex`做保护。
- `make_shared`优点：内存合并分配，减少堆分配次数，缓存友好。

3. **`std::weak_ptr`**

- 依附`shared_ptr`，**不增加引用计数**；用来观测对象是否存活，解决`shared_ptr`循环引用内存泄漏。
- `.lock()`尝试升级为shared_ptr，如果原对象已经析构返回空智能指针。本代码只是演示用法。

## 二、线程池模型：生产者‑消费者

- **生产者**：main主线程循环生成任务，`submit()`上锁压入任务队列，notify_one唤醒工作线程。
- **消费者**：worker工作线程循环`wait`阻塞等待任务；收到唤醒之后上锁取任务，解锁后执行计算。
    
    > ⚠️重点：计算业务逻辑`process_task`必须放在锁之外！否则线程池退化成单线程串行运行。
    
- `cv.wait(lock,谓词)`：解决条件变量**虚假唤醒**，被唤醒之后再次判断条件，不满足继续阻塞。
- `std::atomic<bool> stop_`原子变量，多线程读写不需要锁，标记线程池停止信号。
- 析构函数：设置stop标记，notify_all唤醒全部worker，join等待所有线程返回，防止程序退出线程还在后台跑。

## 四、现存不足（生产环境需要改进）

1. 使用`sleep_for`等待任务完成，属于简单演示；正式代码需要实现任务完成计数、`std::future`或者信号量同步。
2. 没有任务队列上限，如果疯狂submit任务，队列无限膨胀内存暴涨，需要增加队列最大长度，做阻塞/丢弃策略。
3. 没有异常捕获，如果任务内部抛出异常，worker线程会直接崩溃退出。
4. `weak_ptr`这里仅演示语法，业务没有实际依赖。
