# 外部排序

> 针对**无法全部装入内存**的大数据排序：把数据分成块读入内存排序成**归并段**，再**多路归并**。近年考查频率上升（2016、2019、2021、2023、2024 均涉及），重点：**归并趟数、归并段数量、虚段补充计算**。

## 算法思想

**外部排序 = 内部排序 + 归并**：

1. **生成初始归并段**：把文件分成若干块，每块读入内存用内部排序排好写回 → 得到 $N$ 个**初始归并段**
2. **多路归并**：每次把 $k$ 个归并段各取一个块读入内存，用 $k$ 路归并合成更大的段，直到全部合并

**核心公式**：

- 使用 $k$ 路归并、初始归并段 $N$ 个 → 归并趟数 $s = \lceil \log_k N \rceil$
- 总时间 ≈ **内部排序时间 + 读写磁盘时间 + 归并时间**（磁盘 I/O 是瓶颈）
- I/O 次数 = (初始归并段数 + 每趟读写) 相关：**趟数越少 I/O 越少**

**优化手段**：

1. 增加归并路数 $k$（用**败者树**减少选最小值的比较次数：从 $O(k)$ 降到 $O(\log k)$）
2. 减少初始归并段数（**置换-选择排序**生成更长归并段）
3. **最佳归并树**（哈夫曼思想）：归并段长度作为权值构造 k 叉哈夫曼树，使 I/O 最少

## 关键计算：虚段（补充段）

当 $k$ 叉归并树**不是满 k 叉树**时，需补充**虚段（长度为 0 的段）**：

- $k$ 叉哈夫曼树中：若 $(N-1) \bmod (k-1) \ne 0$，需补 $(k-1) - (N-1) \bmod (k-1)$ 个虚段
- 虚段作权值 0 参与归并树构造

## 复杂度

- 归并趟数 $s = \lceil \log_k N \rceil$：$k$ 越大趟数越少，I/O 越少
- 败者树使每趟归并的比较开销从 $O(k)$ 降为 $O(\log k)$
- 磁盘 I/O 次数 = $2 \times N \times (s+1)$（输入+输出 × 每趟）量级

## 易错点

> [!warning] 易错点
> - 归并趟数 $s = \lceil \log_k N \rceil$，**底数是 k（路数）不是 2**
> - 初始归并段数 $N$：由内存大小决定（每段 ≤ 内存可容纳量）
> - **虚段计算**：$k$ 叉归并树不满时必补虚段——近年高频计算题
> - 增加路数 $k$ 会增加**内存缓冲区和比较次数**，但减少 I/O——408 常问权衡
> - 置换-选择不是排序算法而是**生成更长归并段**的技巧
> - 最佳归并树与 [[哈夫曼树]] 同构（权值为归并段长度，WPL = 总 I/O）
