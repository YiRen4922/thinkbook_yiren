# 红黑树

> 2022 年新增考点（已正式纳入考纲）。近似平衡的二叉排序树，**插入最多 2 次旋转、删除最多 3 次旋转**。408 以**性质判断和与 AVL 对比**为主，不需要手写完整插入删除代码。

## 算法思想

红黑树在 BST 基础上给每个结点增加**红/黑**颜色，通过**5 条性质**约束树形，使树高限制在 $O(\log n)$ 且**旋转次数远少于 AVL**：

1. 每个结点是红色或黑色
2. 根结点是**黑色**
3. **所有叶子（空结点 NIL）都是黑色**
4. **不存在两个相邻的红结点**（红结点的孩子必为黑）
5. 任一结点到其**每个叶子的所有路径**包含**相同数量**的黑结点（**黑高相同**）

> 由性质 4、5 可推：红黑树的高度 ≤ $2\log_2(n+1)$，查找 $O(\log n)$。

**插入**：新结点染红插入（不破坏黑高），若双亲为红则违反性质 4，通过**变色/旋转**修复——**最多 2 次旋转**。
**删除**：删除黑结点会破坏黑高，修复**最多 3 次旋转**。

## 与 AVL 对比（408 核心表格）

| 对比项 | 红黑树 | AVL 树 |
|---|---|---|
| 平衡程度 | **近似平衡**（黑高约束） | **严格平衡**（\|BF\| ≤ 1） |
| 树高 | ≤ $2\log_2(n+1)$ | ≈ $1.44\log_2(n+1)$ |
| 查找性能 | 略逊（树稍高） | 更优 |
| 插入/删除调整 | **插入≤2次旋转，删除≤3次旋转** | 插入≤2次，删除可能**多次**回溯 |
| 应用 | C++ map、Java TreeMap、Linux 内核 | 数据库索引场景较少 |

## 代码实现（关键：旋转操作，与 AVL 相同）

```c
// 左旋（RR 型旋转，与 AVL 左旋同构）
void leftRotate(RBNode **T, RBNode *x) {
    RBNode *y = x->rchild;
    x->rchild = y->lchild;
    if (y->lchild) y->lchild->parent = x;
    y->parent = x->parent;
    if (!x->parent) *T = y;
    else if (x == x->parent->lchild) x->parent->lchild = y;
    else x->parent->rchild = y;
    y->lchild = x;
    x->parent = y;
}
// 右旋对称
```

## 时间复杂度

- 查找/插入/删除：**$O(\log n)$**（最坏有保证）
- 空间：$O(n)$（每个结点一个颜色位）

## 易错点

> [!warning] 易错点
> - **红结点不能连续出现**，但黑结点可以连续（性质 4 只限制红红）
> - 空叶子（NIL）算**黑色**，这使"黑高相同"成立
> - 根必须黑、所有叶子黑、黑高相同——判断"是否为合法红黑树"的三把尺
> - **插入最多 2 次旋转、删除最多 3 次旋转**是判断题/选择题高频结论
> - 红黑树是**近似平衡**，AVL 是**严格平衡**；认为"红黑树比 AVL 查找快"是错的（AVL 查找更快，红黑树优势在**调整次数少**）
