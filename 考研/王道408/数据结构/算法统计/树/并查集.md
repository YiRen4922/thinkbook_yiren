# 并查集

> 2022 年新增考点。树形结构表示**集合**：每个集合是一棵树，根为集合代表。支持**查（Find）**与**并（Union）**，配合**路径压缩**和**按秩合并**后近 $O(1)$。408 常与 [[最小生成树：Prim与Kruskal]] 的 Kruskal 判环结合考查。

## 算法思想

**核心思想**：用**森林**表示若干互不相交的集合，树根是集合的"代表"：

- **Find(x)**：返回 x 所在树的根（集合代表）——沿双亲链向上
- **Union(a, b)**：把两棵树的根合并——一个根成为另一个的双亲

**两个优化（408 常考）**：

1. **路径压缩**：Find 时把路径上所有结点的双亲直接指向根 → 下次 Find 更快
2. **按秩合并**：秩（树高/规模）小的树挂到秩大的树下 → 防止树退化为单链

## 代码实现

```c
int parent[MAXSIZE];                   // parent[i] 为 i 的双亲，根的双亲为自身
int rank[MAXSIZE];                     // 秩（近似树高）

// 初始化：每个元素自成一棵集合
void Init(int n) {
    for (int i = 0; i < n; i++) { parent[i] = i; rank[i] = 0; }
}

// Find：返回根（递归版路径压缩）
int Find(int x) {
    if (parent[x] != x) parent[x] = Find(parent[x]);  // 路径压缩
    return parent[x];
}

// Union：按秩合并
void Union(int a, int b) {
    int ra = Find(a), rb = Find(b);
    if (ra == rb) return;              // 已在同一集合
    if (rank[ra] < rank[rb]) parent[ra] = rb;
    else if (rank[ra] > rank[rb]) parent[rb] = ra;
    else { parent[rb] = ra; rank[ra]++; }
}
```

## 时间复杂度

- 朴素实现：Find $O(h)$（$h$ 为树高，最坏 $O(n)$）
- **路径压缩 + 按秩合并**：摊还 $\alpha(n)$（反阿克曼函数，几乎 $O(1)$）
- 空间：$O(n)$

## 易错点

> [!warning] 易错点
> - **路径压缩发生在 Find 时**，Union 只合并根，不主动压缩
> - Union 先 Find 再合并，**同一集合（根相同）直接返回**
> - 按秩合并不看结点个数，看**秩（高度）**；两秩相等时合并后秩 +1
> - 408 手算：给出 Union 序列，画出**森林形态**（双亲表示）
> - Kruskal 判环：两端点 Find 结果相同说明已经连通，**不能加这条边**
