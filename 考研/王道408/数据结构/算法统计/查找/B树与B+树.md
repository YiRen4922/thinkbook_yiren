# B树与B+树

> 多路平衡查找树：每个结点可存多个关键字、有多棵子树，用于**磁盘存储**（一次读一个结点）。408 A 级考点，B 树考频超 70% 且难度逐年上升：高度计算、**插入分裂、删除合并**手算；B+ 树记与 B 树的三点区别。

## 算法思想

**m 阶 B 树**（m 叉平衡查找树）：

- 每个结点最多 **m 棵子树、m-1 个关键字**
- 除根外，每个结点至少 $\lceil m/2 \rceil$ 棵子树（$\lceil m/2 \rceil - 1$ 个关键字）
- **根**：至少 2 棵子树（除非是叶子）
- 所有**叶子在同一层**（绝对平衡，不含信息）
- 结点内关键字**有序**

**插入**：先查找到叶子结点的插入位置（沿查找失败路径），插入后若关键字数 $> m-1$ 则**分裂**——中间关键字上移，左右各成结点。

**删除**：需要时**借位（兄弟）或合并（父结点下沉）**，并可能逐层向上调整。

## 代码实现（结构定义，408 主要考手算）

```c
#define MAXKEY 4                       // 5 阶 B 树
typedef struct BTNode {
    int keynum;                        // 关键字个数
    int key[MAXKEY];                   // 关键字数组
    struct BTNode *child[MAXKEY + 1];  // 子树指针（比关键字多 1）
    struct BTNode *parent;
} BTNode;
```

> 408 不要求默写 B 树完整插入/删除代码，重点是**手算分裂/合并过程**和**高度计算**。

## 时间复杂度

- 查找/插入/删除：$O(\log_m n)$（树高低，磁盘访问次数少）
- 树高 $h$ 满足：$h \le \log_{\lceil m/2 \rceil}\frac{n+1}{2} + 1$
- 一次查找的磁盘 I/O 次数 = 树高（每次读一个结点）

## 易错点

> [!warning] 易错点
> - **关键字数 = 子树数 - 1**（m 阶：最多 m-1 个关键字、m 棵子树）
> - 分裂：关键字个数达到 **m** 时分裂（不是 m-1），中间关键字上提
> - **根结点特例**：允许少于 $\lceil m/2 \rceil$ 棵子树（最少 2 棵/1 个关键字）
> - 所有叶子在同一层——"绝对平衡"，插入从底部分裂
> - 删除时的借位/合并不是所有教材细节都考，但**分裂**是必考手算点

## B+树与 B 树的区别（408 必背三点）

| 对比 | B 树 | B+树 |
|---|---|---|
| 叶子结点 | 存储所有信息 | **叶子结点包含全部关键字**，且按序链接成链表（支持顺序查找） |
| 非叶子结点 | 存关键字（可存信息） | **只存索引**（关键字作索引，不存信息），信息全在叶子 |
| 查找方式 | 找到即止 | **任何查找都必须走到叶子**（路径等长），支持范围查找 |

> B+树的两个分支指针（关键字与子树同为 n+1 规约）可能出细节题：B+树中每个结点关键字数 = 子树数。
