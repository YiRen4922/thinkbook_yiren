## 串 · 考研408核心笔记（四）KMP算法

> **KMP 算法**（Knuth–Morris–Pratt，由 D.E. Knuth、J.H. Morris、V.R. Pratt 于 1977 年提出）是对朴素模式匹配的改进，核心思想：**主串指针 $i$ 永不回溯**，失配时模式串指针 $j$ 借助 **next 数组**跳转到合理位置。整体时间复杂度 $O(n+m)$，是 408 串章节的**绝对重点**，几乎每年都有选择题或大题。

本文讲 next 数组的**含义与使用**；[[考研/王道408/数据结构/4、串/求next数组]] 讲它的递推求法。


### 1. 朴素算法的痛点回顾

主串 $S = 'abaabaabcabaabc'$，模式串 $T = 'abaabc'$。第 1 趟比较到第 6 个字符才失配，此时已经确认：

- $S[1..5] = T[1..5] = 'abaab'$

朴素算法会让 $i$ 回到 2，重新比较——但"$S[1..5]$"这段信息明明可以复用：

```
第1趟失配时：  S: a b a a b a …
               T: a b a a b c
                   ↑ i=6, j=6 失配

KMP 的洞察：T[1..5]='abaab' 的最长相等前后缀是 'ab'（长度2），
所以 j 直接跳到 3 即可 —— 'ab' 这一段已经和主串匹配过了，不用再比。
```

### 2. 核心思想

失配于 $T[j]$ 时，$T[1..j-1]$ 已经与主串某段匹配。若 $T[1..j-1]$ 的**最长相等前后缀**长度为 $L$，那么：

- 后缀那部分（长度 $L$）已经在主串中比对过
- 模式串只需把"前缀"挪过来对齐 ⇒ **$j$ 跳到 $L + 1$，$i$ 不动**

由此定义 **next 数组**：

$$
\text{next}[j] = \begin{cases}
0 & j = 1 \\
\max\{k \mid 1 \le k < j,\ \ T[1..k-1] = T[j-k+1..j-1] \text{ 且 } k>1\} + 1 & j \ge 2 \\
1 & \text{不存在相等前后缀时}
\end{cases}
$$

> [!important] next[j] 的通俗含义（务必背熟）
> **next[j] = 模式串第 j 个字符失配时，j 应该跳转到的位置。**
> 其数值 = 前 $j-1$ 个字符组成的子串中，**最长相等前后缀长度 + 1**。
> 特殊的：$\text{next}[1] = 0$（表示用主串下一个字符与模式串第 1 个字符重新比较）。

**前后缀定义**（不能含整个串）：

- 前缀：除最后一个字符外，串的所有**头部**子串
- 后缀：除第一个字符外，串的所有**尾部**子串

例如 $'abab'$：前缀 $\{a, ab, aba\}$，后缀 $\{b, ab, bab\}$，最长相等前后缀为 $'ab'$，长度 $2$。


### 3. next 数组举例

$T = 'abaabc'$：

| $j$ | 前 $j-1$ 个字符 | 最长相等前后缀 | 长度 $L$ | $\text{next}[j] = L+1$ |
| --- | --- | --- | --- | --- |
| 1 | — | — | — | **0**（特殊） |
| 2 | `a` | 无 | 0 | 1 |
| 3 | `ab` | 无 | 0 | 1 |
| 4 | `aba` | `a` | 1 | 2 |
| 5 | `abaa` | `a` | 1 | 2 |
| 6 | `abaab` | `ab` | 2 | 3 |

$$
\text{next} = [0, 1, 1, 2, 2, 3]
$$


### 4. KMP 算法实现（下标从 1）

```cpp
// 已知 next 数组，用 KMP 求 T 在 S 中首次出现的位置
int Index_KMP(SString S, SString T, int next[]) {
    int i = 1, j = 1;
    while (i <= S.length && j <= T.length) {
        if (j == 0 || S.ch[i] == T.ch[j]) {   // j==0：主串换下一字符，j 回到 1
            ++i;
            ++j;
        } else {
            j = next[j];                       // 失配：仅移动 j，i 不回溯！
        }
    }
    if (j > T.length) return i - T.length;     // 匹配成功
    else return 0;                             // 匹配失败
}
```

> [!warning] 两个关键点
> 1. `j == 0` 的情况来自 `next[1] == 0`：此时应**主串后移、j 回到 1**（`++i; ++j` 后 $j$ 恰好变为 1）
> 2. KMP 中**只有 `j` 在变，`i` 从未回退**——这正是 $O(n+m)$ 的原因


### 5. 匹配过程演示（mermaid）

$S = 'abaabaabcabaabc'$，$T = 'abaabc'$，$\text{next} = [0,1,1,2,2,3]$：

```mermaid
flowchart LR
    subgraph 主串 S
        S1["1:a"] --> S2["2:b"] --> S3["3:a"] --> S4["4:a"] --> S5["5:b"] --> S6["6:a"] --> S7["7:a"] --> S8["8:b"] --> S9["9:c"]
    end
    subgraph 第1趟失配[j=6]
        T1["1:a"] --> T2["2:b"] --> T3["3:a"] --> T4["4:a"] --> T5["5:b"] --> T6["6:c[失配]"]
    end
    subgraph next[6]=3 → j 跳到3，i 停在6
        T1x["3:a"] --> T2x["4:a"] --> T3x["5:b"] --> T4x["6:a"]
    end
```

第 1 趟失配于 $S[6]$ vs $T[6]$，$\text{next}[6] = 3$，于是 $j=3$ 继续与 $S[6]$ 比较：$T[3]='a'$，$S[6]='a'$ ✔，继续推进，最终匹配成功。

> [!tip] 体会
> 整趟匹配中 $i$ 单调递增，只走了 $n$ 步；$j$ 最多回退 $n$ 次。因此**匹配阶段是 $O(n)$**，加上预处理 next 的 $O(m)$，总复杂度 $O(n+m)$。


### 6. 为什么主串可以不回溯？（正确性论证）

失配于位置 $j$ 时，已知 $T[1..j-1] = S[i-j+1..i-1]$。

设 $T[1..j-1]$ 的最长相等前后缀长度为 $L< j-1$，则：

$$
T[1..L] = T[j-L..j-1] = S[i-L..i-1]
$$

即主串 $S$ 在 $i$ 之前的 $L$ 个字符恰好等于模式串的前 $L$ 个字符——**把 $j$ 跳到 $L+1$ 后，前缀部分无需再比较**，且能证明任何"跳过"的位置 $k < L+1$ 都不可能匹配成功（否则前后缀长度比最长还要长，矛盾）。故 $i$ 无需回溯是**安全的**。


### 7. 复杂度对比

| 对比项 | 朴素匹配（BF） | KMP |
| --- | --- | --- |
| 主串指针 $i$ | 失配时回溯 | **永不回溯** |
| 模式串指针 $j$ | 每次回到 1 | 按 next 跳转 |
| 预处理 | 无 | 求 next：$O(m)$ |
| 匹配阶段 | 最坏 $O(nm)$ | $O(n)$ |
| 总复杂度 | 最坏 $O(nm)$ | **$O(n+m)$** |


### 8. 408 常考点

| 考点 | 说明 |
| --- | --- |
| next[j] 的含义 | 第 $j$ 个字符失配时 $j$ 的跳转位置 = 最长相等前后缀长度 + 1 |
| next[1] = 0 | 约定边界（j=0 时主串后移、j 复位为 1） |
| 前后缀 | 均**不含整个串**；最长相等前后缀长度由比较得出 |
| 主串不回溯 | KMP 与朴素算法的本质区别 |
| 时间复杂度 | 求 next $O(m)$ + 匹配 $O(n)$ = $O(n+m)$ |
| KMP 能改进什么 | 只有 $j$ 的回退由 next 精确定位，避免了 $i$ 的反复扫描 |
