## 串 · 考研408核心笔记（二）存储结构

> 串的存储结构有 **三种**：**定长顺序存储**、**堆分配存储（变长）**、**链式存储（块链）**。408 常考定长顺序存储下"串长的表示方式"和模式匹配中"下标从 1 开始"的约定；块链只考概念与存储密度计算。


### 1. 定长顺序存储

用**一组地址连续的存储单元**存放串的字符序列（本质是字符数组）。

```cpp
#define MAXLEN 255                       // 串的最大长度

typedef struct {
    char ch[MAXLEN];     // 每个分量存储一个字符
    int length;          // 串的实际长度
} SString;               // 定长顺序存储
```

**特点**：

- 长度**固定**，不能超过 `MAXLEN`
- 超过 `MAXLEN` 的部分会被**截断**（超长内容丢失，运算结果"截尾"）
- 支持**随机存取**第 $i$ 个字符：$O(1)$

**串长（长度）的三种表示方式**：

| 方式          | 说明                  | 例子                       |
| ----------- | ------------------- | ------------------------ |
| `length` 变量 | 结构体中单独记录长度（王道默认）    | `S.length = 5`           |
| `ch[0]` 存长度 | 用 0 号单元存放串长         | `ch[0]=5`，字符从 `ch[1]` 开始 |
| `'\0'` 结尾   | C 风格字符串，遇 `'\0'` 停止 | `char s[] = "abc"`       |

> [!warning] 408 关键约定（务必记住）
> 王道《数据结构》：模式匹配（朴素匹配 / KMP 求 next）中，**串的下标从 1 开始**——字符存于 `ch[1] ~ ch[length]`，`ch[0]` 闲置（或放长度）。求 next 数组的代码、例题全部建立在这个约定上。官方教材（严蔚敏）用 `ch[0]` 存长度，效果等价。


### 2. 堆分配存储（变长顺序存储）

串值仍然存放在**连续空间**中，但空间**按需动态分配**，长度可变。

```cpp
typedef struct {
    char *ch;        // 按串长分配存储区，ch 指向串的基地址
    int length;      // 串的长度
} HString;
```

**特点**：

- 长度不受预分配上限限制
- C 语言用 `malloc`/`free` 管理，C++ 用 `new`/`delete[]`
- 依然支持随机存取，但每次运算可能涉及**重新分配与复制**

```cpp
// 初始化
void InitString(HString &S) {
    S.ch = NULL;
    S.length = 0;
}

// 赋值（字符串常量 -> 堆串）
void StrAssign(HString &S, char *cstr) {
    int len = 0;
    while (cstr[len] != '\0') len++;          // 求常量串长
    if (S.ch) free(S.ch);                     // 释放旧空间
    S.ch = (char*)malloc(len * sizeof(char));
    for (int i = 0; i < len; i++) S.ch[i] = cstr[i];
    S.length = len;
}
```


### 3. 链式存储（块链）

用链表存储串，问题是：若**每个结点只存 1 个字符**，指针开销远大于数据本身，存储密度极低。改进方案是**每个结点存多个字符**（结点大小为块长）。

```cpp
#define CHUNKSIZE 4          // 结点大小：每个结点存 4 个字符

typedef struct Chunk {
    char ch[CHUNKSIZE];      // 数据域：一串字符
    struct Chunk *next;      // 指针域
} Chunk;

typedef struct {
    Chunk *head, *tail;      // 头指针、尾指针
    int length;              // 串长
} LString;
```

**存储密度**：

$$
\text{存储密度} = \frac{\text{串值所占存储}}{\text{结点实际占用存储}}
= \frac{\text{CHUNKSIZE}}{\text{CHUNKSIZE} + 1}
$$

（分母中 $+1$ 是 next 指针占用的空间，按"1 个结点大小"计）

> [!note] 结点大小的影响
> - 结点 = 4 字符：密度 = $4/5 = 80\%$，较高
> - 结点 = 1 字符：密度 = $1/2 = 50\%$，很低（这就是"一个结点只存一个字符"的块链效率差的原因）
> - 结点越大存储密度越高，但**取子串、插入、连接**等运算越不便（可能要整块搬运）

**特点**：链式存储对串并不友好——串的操作多是整体/子串级操作，链表随机存取能力差，故**除概念题外几乎不用链式存储**。


### 4. 三种存储结构对比

| 对比项 | 定长顺序 | 堆分配 | 块链 |
| --- | --- | --- | --- |
| 空间 | 固定（预分配） | 按需动态分配 | 按结点分配 |
| 长度 | 固定，可能截断 | 可变 | 可变 |
| 随机存取 | ✅ $O(1)$ | ✅ $O(1)$ | ❌ 需遍历 |
| 存储密度 | 高（几乎 100%） | 高 | 低（含指针开销） |
| 实现复杂度 | 低 | 中 | 较高 |
| 使用场景 | 王道例题/考试默认 | 实际工程（`std::string` 类似） | 概念了解即可 |


### 5. 基本操作的代码实现（定长顺序存储）

以下三个操作是 [[考研/王道408/数据结构/4、串/串的定义和基本操作|串 ADT]] 中最常考的实现题，全部基于**定长顺序存储、下标从 1 开始**（`ch[0]` 闲置）的约定。

#### 5.1 求子串（SubString）

```cpp
// 用 Sub 返回串 S 的第 pos 个字符起长度为 len 的子串
bool SubString(SString &Sub, SString S, int pos, int len) {
    if (pos < 1 || len < 0 || pos + len - 1 > S.length)
        return false;                    // 位置或长度越界：非法参数
    for (int i = pos; i < pos + len; i++)
        Sub.ch[i - pos + 1] = S.ch[i];   // 复制到 Sub，从下标 1 起存放
    Sub.length = len;
    return true;
}
```

> [!warning] 易错点
> ① 越界判断条件 `pos + len - 1 > S.length` 必须用到**最后一个字符的下标**，容易漏写；② 子串在 `Sub` 中仍从下标 **1** 开始存放（映射：$S$ 的下标 $i$ → $Sub$ 的下标 $i - pos + 1$），不要沿用 `pos`。

#### 5.2 比较操作（StrCompare）

```cpp
// 比较 S 和 T：S<T 返回负数；S=T 返回 0；S>T 返回正数（字典序）
int StrCompare(SString S, SString T) {
    for (int i = 1; i <= S.length && i <= T.length; i++) {
        if (S.ch[i] != T.ch[i])
            return S.ch[i] - T.ch[i];    // 第一个不同字符的编码差，正负即大小
    }
    return S.length - T.length;          // 其中一个是另一个的前缀，比长度
}
```

> [!note] 与字典序的对应
> 比较规则即 [[字典序]]：逐字符比编码，遇到第一对不同字符时编码差的正负决定大小；若前 $n$ 个字符全相等（某串是另一串前缀），较短的串较小——代码最后的 `S.length - T.length` 正是实现这一条。

#### 5.3 定位操作（Index）

```cpp
// 返回模式串 T 在主串 S 中从第 pos 个字符起首次出现的位置，否则返回 0
int Index(SString S, SString T, int pos) {
    int i = pos, j = 1;
    while (i <= S.length && j <= T.length) {
        if (S.ch[i] == T.ch[j]) {        // 字符相等，继续匹配后继
            ++i; ++j;
        } else {                         // 失配：主串回溯，模式串回 1
            i = i - j + 2;
            j = 1;
        }
    }
    if (j > T.length) return i - T.length;   // 匹配成功，返回起始位置
    else return 0;                           // 匹配失败
}
```

> [!tip] 三种实现的复杂度
> | 操作 | 时间复杂度 | 说明 |
> | --- | --- | --- |
> | SubString | $O(len)$ | 只需复制子串长度个字符 |
> | StrCompare | $O(\min(\text{S.length}, \text{T.length}))$ | 最多比较到较短串结尾 |
> | Index（朴素） | 最坏 $O(nm)$ | 主串每次失配都回溯，详见 [[考研/王道408/数据结构/4、串/朴素模式匹配算法]]；KMP 版可到 $O(n+m)$ |

> [!note] 三个操作的依赖链
> `Index` 可借助 `SubString` + `StrCompare` 实现（逐位取子串并比较），也可直接用双指针（如上）。**408 大题常让你手写其中某两个**，模板代码务必默写熟练。


### 6. 408 常考点

| 考点 | 说明 |
| --- | --- |
| 下标从 1 开始 | 模式匹配、next 数组的默认约定，`ch[0]` 闲置 |
| 截断问题 | 定长存储下，串长超过 `MAXLEN` 时超出部分被舍去 |
| 存储密度 | $\frac{\text{数据存储}}{\text{结点总存储}}$，结点越大密度越高 |
| 三种表示法 | `length` 变量 / `ch[0]` 存长 / `'\0'` 结尾 |
| 判断 | "串的链式存储每个结点只存一个字符" — 存疑，标准实现是块链（多字符/结点） |
