## 串 · 考研408核心笔记（三）朴素模式匹配算法（BF）

> **模式匹配（Pattern Matching）**：在主串 $S$ 中寻找与模式串 $T$ 相等的子串，并返回 $T$ 首次出现的位置（即实现 `Index` 操作）。朴素算法又称 **BF 算法（Brute Force）**，思路简单直接——**逐个位置暴力尝试**，最坏时间复杂度 $O(nm)$，是理解 KMP 的跳板。


### 1. 问题定义

- 主串 $S$：长度为 $n$
- 模式串 $T$：长度为 $m$（$m \le n$）
- 目标：在 $S$ 中找出 $T$ 首次出现的位置；若不存在返回 $0$

下标统一从 1 开始（[[考研/王道408/数据结构/4、串/串的存储结构]] 中的约定）。

$$
S = 'abaabaabcabaabc', \qquad T = 'abaabc'
$$


### 2. 算法思想

从主串第 $pos$ 个字符起，与模式串第一个字符逐个比较：

1. 若 $S[i] = T[j]$：两指针同时后移，继续比较下一对字符
2. 若 $S[i] \ne T[j]$：**主串指针回溯**，模式串指针回到 1，从主串的**下一个位置**重新匹配
3. 若 $j > m$：匹配成功，返回 $i - m$（子串在主串中的起始位置）

**回溯公式（核心）**：失配时，本轮匹配起点是 $i - (j - 1) = i - j + 1$，下一轮起点右移一位：

$$
i = i - j + 2, \qquad j = 1
$$

> [!note] 为什么是 $i - j + 2$？
> 失配时 $i$、$j$ 已同时移动了 $j-1$ 次（成功匹配了 $j-1$ 个字符），本轮主串起点为 $i-j+1$；下一轮起点 = 起点 + 1 = $i - j + 2$。


### 3. 算法实现（王道风格，下标从 1）

```cpp
// 返回模式串 T 在主串 S 中从第 pos 个字符起首次出现的位置，否则返回 0
int Index(SString S, SString T, int pos) {
    int i = pos, j = 1;
    while (i <= S.length && j <= T.length) {
        if (S.ch[i] == T.ch[j]) {      // 字符相等：继续匹配后继字符
            ++i;
            ++j;
        } else {                       // 失配：主串指针回溯，模式串回到头部
            i = i - j + 2;
            j = 1;
        }
    }
    if (j > T.length) return i - T.length;   // 匹配成功，返回起始位置
    else return 0;                            // 匹配失败
}
```


### 4. 手动模拟示例

$S = 'abaabaabcabaabc'$，$T = 'abaabc'$（主串从 $pos=1$ 开始）：

| 趟数 | 对齐位置 | 比较过程 | 结果 |
| --- | --- | --- | --- |
| 第 1 趟 | $S_1$ | `abaab(a)` vs `abaab(c)`，前 5 个相同，第 6 个失配 | 失配，$i$ 回退到 2 |
| 第 2 趟 | $S_2$ | `b` vs `a`，第 1 个字符就失配 | 失配，$i$ 到 3 |
| 第 3 趟 | $S_3$ | `a` vs `a` 相等，继续 | 继续… |
| … | … | … | … |
| 第 5 趟 | $S_4 = S_5$? | `abaabc` 全部匹配 | ✅ 成功，返回 6 |

> [!tip] 观察
> 第 1 趟已经确认 $S[1..5] = T[1..5]$，第 2、3 趟又重新比较了这些"已知信息"——**这就是朴素算法的浪费之处**，KMP 正是抓住这一点来优化。


### 5. 时间复杂度分析

| 情况 | 说明 | 复杂度 |
| --- | --- | --- |
| 最好 | 第 1 趟第 1 个字符就匹配成功（或首字符即失配），比较 $1$ 次 | $O(1)$ ~ $O(m)$ |
| 平均 | 每个位置试比较常数个字符 | $O(n + m)$ |
| 最坏 | 每趟都比较到模式串最后一个字符才失配，共 $(n-m+1)$ 趟，每趟 $m$ 次比较 | $O(nm)$ |

**最坏情况实例**：$S = '0000000001'$（9 个 0 加 1），$T = '0001'$——每趟都匹配到第 4 个字符才失配，比较次数约为 $(9-4+1) \times 4 = 24$ 次。

> [!warning] 记住结论
> 朴素模式匹配的**最坏时间复杂度为 $O(nm)$**，这是 408 选择题高频结论；当题目给"主串长 n、模式串长 m"问朴素匹配最坏比较次数时，答案即 $O(nm)$。


### 6. 朴素算法的缺点 → 引出 KMP

1. **主串指针 $i$ 频繁回溯**：失配后要回到本轮起点+1，已经扫描过的字符被反复比较
2. **已匹配信息被丢弃**：$S[1..5] = T[1..5]$ 这个事实在第 2、3 趟完全没有被利用
3. 每一次失配都让 $j$ 从 1 重新开始，即使模式串自身含有重复结构

**KMP 的核心改进**：主串指针 $i$ **永不回溯**，$j$ 借助 **next 数组**跳转到合理位置 → 总复杂度降至 $O(n + m)$。


### 7. 408 常考点

| 考点 | 说明 |
| --- | --- |
| 回溯公式 | $i = i - j + 2$，$j = 1$ |
| 最坏复杂度 | $O(nm)$（$S='000…01$，$T='00…1'$ 型数据） |
| 最好复杂度 | 首字符即失配时接近 $O(n)$ |
| 返回值 | 成功返回 $i - m$，失败返回 0 |
| 与 KMP 对比 | 朴素丢信息、回溯 $i$；KMP 不回溯 $i$、仅动 $j$ |
